## Context

Decision 7 of `docs/design/engine.md`: a pattern is compiled to a small instruction set and run by a backtracking matcher with an explicit backtrack stack, every step charged to the step budget, because the semantics of ECMAScript (ordered alternation, captures reset per iteration, backreferences, lookahead and lookbehind) are defined by backtracking (22.2.2, `#sec-pattern-semantics`), and an explicit stack means no Rust recursion: a hostile pattern such as `(a+)+$` ends at the budget and cannot hang the host. Decision 3, "Depth bounds": the matcher is a loop with an explicit backtrack stack, bounded by the step budget. This story writes the compiler and the matcher of `swell-regexp` over the tree of `story:regexp-crate-and-pattern-parser`, in the crate alone (no heap value, decision 2), so that `story:regexp-objects-exec-and-literals` runs them from `RegExp`. It runs beside `story:regexp-literal-early-errors`, which writes `crates/syntax` and does not use the matcher.

Lifts of the consumer (`docs/plan/slice-05/consumer-regexps.tsv`): none by itself; the test `the_constructs_of_the_consumer_table_match` below matches, in the crate, one pattern per row written for it with the constructs of that row (nothing of the downloaded files is copied), so the matcher the consumer needs is shown before `RegExp` exists. No test262 case runs on the crate alone; the cases its matching lifts are on the lists of `story:regexp-objects-exec-and-literals` and `story:regexp-symbol-methods-and-string-match-search`.

Design it builds on: decision 7 of `docs/design/engine.md`, with its paragraphs "How `swell-regexp` charges its work" (item 1, the trait of `story:regexp-crate-and-pattern-parser`; item 3, positions), "What one step of the matcher is" and "No Rust recursion in the parser and the compiler of a pattern"; decision 3 ("The step budget", "Depth bounds"); decision 5 (the two stored forms of a String, which the matcher reads in place).

## Change

Failing tests first: the tests below are written before the code and do not compile on the base of the unit (no compile or match entry exists in the crate).

- `crates/regexp/src/program.rs` and `src/compile.rs` (new): CompilePattern (`#sec-compilepattern`) of the tree to a program, one vector of instructions, by a walk of the tree with a worklist and no Rust recursion (decision 7, "No Rust recursion in the parser and the compiler of a pattern"): instructions for a code unit or a code point, a class (sorted, disjoint ranges; the sort of a class's n ranges is the one part above linear, n log n), `.` with and without `s`, `^` and `$` with and without `m`, `\b` and `\B`, a choice (greedy or lazy) and a jump, the start and end of a capture, the clearing of the captures of a quantified atom at each iteration (`#sec-runtime-semantics-repeatmatcher-abstract-operation`, step 4) as one instruction naming a range of capture numbers, a counter for `{n,m}` (not n copies) with the empty check of step 2.b, a backreference (by number, and by name as the list of the groups of that name, duplicates included), the entry and exit of a lookaround with its direction, and the end of the match. So the compile step is linear in the pattern's length: a bounded number of instructions per node. Each instruction is documented with what it does to the state. The program is charged through the trait before it grows, and `Program::heap_bytes` gives what its owner credits when it drops it; the compile step charges no step and polls the interrupt at least once per 4,096 nodes it visits. `\d`, `\w` and `\b` are those of `#sec-compiletocharset` without the flag `i` (ASCII); `\s` is WhiteSpace and LineTerminator (`#sec-white-space`, with `swell_unicode::is_space_separator` for `Zs`). The modifiers `m` and `s` of `(?ms-ms:...)` set the mode of their atoms.
- Refused here, a refusal of slice 5 (decision 7, "Refusals until the later stories of slice 5": `case-insensitive matching is not supported before slice 5`, the message exact): a pattern with the flag `i` or a modifier `i`, refused by CompilePattern after the parse, so a pattern with `i` and an early error answers the early error; Canonicalize (`#sec-runtime-semantics-canonicalize-ch`) needs the tables of `story:case-mapping-tables-and-string-case-methods` and of case folding, and `story:regexp-case-insensitive-matching-and-modifiers` lifts it.
- `crates/regexp/src/matcher.rs` (new): the match of a program against a subject from one start index, and the search that tries each start index from there (the loop of RegExpBuiltinExec, `#sec-regexpbuiltinexec`, steps 11 to 13: from one try to the next by the amount of AdvanceStringIndex, `#sec-advancestringindex`, and only the start index when the search is sticky), answering the captures (each a range or unset, group 0 the match) or no match. Positions (decision 7, "How `swell-regexp` charges its work", item 3): code unit indices in every mode, `u` and `v` included; the start index a caller passes and every position the match answers count UTF-16 code units, as `lastIndex`, `index` and `indices` do, so no side converts anything. The subject is the code units of a String read in place in either stored form of decision 5 (a `Subject` of the crate over Latin-1 bytes or 16-bit units, each read as a code unit) and never copied for a match. Under `u` (and `v`) the matcher reads a code point at a code unit position (a surrogate pair two units and one code point, a lone surrogate one unit) and moves by its length; a start index on the second unit of a pair starts the first try at the pair's first unit (the character "obtained from element lastIndex of string"), and the caller keeps its `lastIndex`. A loop over the instructions with an explicit backtrack stack of entries (the instruction to resume, the position, and the captures and counters to restore), no Rust recursion. The semantics of 22.2.2: alternatives in order; greedy and lazy quantifiers; the empty check; captures reset per iteration; a backreference to an unset group matches the empty String; a lookahead is atomic (no backtracking into it), keeps the captures of a positive one and resets those of a negative one; a lookbehind reads right to left and fills its captures so; duplicate named groups answer the group that took part in the match.
- Steps and memory (decision 7, "What one step of the matcher is"): a match spends exactly one step per start index its search tries, one per instruction it runs, one per entry it takes from the backtrack stack, and one per code unit a backreference compares, charged before the comparison; `/a/` against `ba` spends 5. It takes its steps by grants of at most 4,096 before it runs them, asks for the next grant when one is spent (a backreference that needs more than is left takes further grants first), and when the match ends with a match or with no match returns what it was granted and did not run, so the steps charged are the units run and the interrupt is read at least once per 4,096 of them; a refused grant stops the match. The backtrack stack, the captures and the counters grow by capacity, each growth charged before it is made, and every byte is credited on every way out of the match: a match, no match and a stop. `crates/regexp/src/budget.rs` is not written: the trait of `story:regexp-crate-and-pattern-parser` has the grant and the return this story calls; an error in it goes back to that story.
- `crates/regexp/src/lib.rs`: the `mod` lines and the exports of compile, the program, the match and the search.
- Tests (`crates/regexp/tests/`, new files, `main.rs` generated): `matcher.rs`: a table of rows (pattern, flags, subject, start, expected captures as code unit ranges or no match) that reaches every instruction and every point of the semantics above, with and without `u`, the forms of B.1.2 included; `the_constructs_of_the_consumer_table_match`; `positions_are_code_unit_indices_in_every_mode` (under `u` a match after a surrogate pair answers the code unit index past it, and a start index on the second unit of a pair starts the try at its first); `a_latin1_and_a_16_bit_subject_match_alike` (the same rows over both stored forms); `sticky_search_tries_one_index_and_unicode_search_steps_over_a_pair`; `case_insensitive_matching_is_a_refusal_of_slice_5` (the flag `i` and `(?i:a)` answer the refusal with its exact message; `(?i-i:a)` answers its early error). `budgets.rs`: `catastrophic_backtracking_ends_at_the_step_budget` (`(a+)+$` against 10,000 `a` and a `!`, with a step budget of 1,000,000: the stop over the step budget, no hang), `the_steps_of_a_match_are_exactly_its_units` (a recording budget: `/a/` against `ba` is charged 5 steps net of the return; a backreference of 1,000 code units is charged 1,000 steps for its comparison; no grant is larger than 4,096 and none is asked after a refusal), `a_refused_grant_stops_the_match_before_the_next_unit`, `a_backtrack_stack_past_the_memory_budget_stops_the_match` (`(?:a|b)*c` against 100,000 `a` with 64 KiB), `the_stack_and_the_captures_are_credited_on_every_way_out`, `an_interrupt_stops_a_long_match`, `the_compiler_and_the_matcher_use_no_rust_recursion` (a pattern of 10,000 nested groups compiled and matched, and `a*` against 1,000,000 units, on a thread of 64 KiB), `the_compile_step_is_linear` (`a{1000000}` compiles to a bounded number of instructions). No unit test in `src/`: every test reads the crate's public interface.
- Time ("Tests stay fast", the `AGENTS.md` of the folder that holds the repository, and `AGENTS.md`, "Commands and the gate"): a test is terminated at 60 s and counts as failed, and the gate fails when the wall time of its test steps passes 120 s. A test stays under 1.5 CPU seconds alone in the default mode of the gate, under 2 s with a collection at every safe point, and under 2.5 s at its full count (`SWELL_FULL_COUNTS=1`) in either mode, measured with its test binary run directly with `--exact <name> --test-threads 1` under `time` of the shell (user plus system); a language script stays under 0.5 CPU seconds per run. The unit times each test before it adds it and names in its report each one over 1 CPU second with its time; a product several tests share is built once inside one test function or is a committed file, never in a `static` (the steps run a process per test); no test makes a network request; the unit runs the test binaries of its own change, never the whole gate and never a whole-workspace test run. Builds and tests go through the pool: `cargo` is the shim of the pool, anything else that compiles or tests is prefixed `slot`, a pool job ends after 10 minutes unless it names its time (`slot --timeout 30m`, the most), and a script that measures or waits runs without the prefix. No Python in any tool, test or command. The budget tests are bounded by their budgets (1,000,000 steps, 64 KiB); each is timed and none is expected over 0.5 CPU seconds.
