## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8). This story is the grammar of a class (`#sec-class-definitions`: ClassDeclaration, ClassExpression, ClassTail, ClassHeritage, ClassBody with MethodDefinition elements, `static`, computed keys, empty elements) and its early errors (`#sec-class-definitions-static-semantics-early-errors`: one `constructor`, a `constructor` that is no special method, no `static prototype`, the strict mode of class code `#sec-strict-mode-code`, the class name's binding and its redeclaration in a block, a switch and a script, `#sec-block-static-semantics-early-errors`), parsed to the class tree of item 1 of "Classes" and held: the parse goes on to its end, its early errors are answered, and a source with a class and no error answers `class is not supported before slice 8` (held, `Parser::held`). It runs nothing. It needs no other story of slice 8: order 1, built beside `story:new-target-meta-property` and `story:super-property-and-super-syntax`.

It owns `Parser::hold`, the one helper that holds a refusal to the end of the parse: this story holds `class` (lifted by `story:class-definition-evaluation`) and `class heritage` (lifted by `story:derived-classes-and-super-call`); `story:class-element-syntax-and-early-errors` calls it for the element holds. The parts of a class body that story brings are refused here at their token: a field (`class field is not supported before slice 8`) and a static block (`class static block is not supported before slice 8`); a private name keeps the lexer's refusal (`crates/syntax/src/lexer.rs`, `refused("private name", 8)`). A class method is parsed through `method_head`, where `story:super-property-and-super-syntax` (built at the same time) admits `super.x`; a SuperCall in a class is an early error until `story:derived-classes-and-super-call`, whose list holds those cases.

On the base (the code of `62c7cf59`; the unit reads every named site again on its own base): `crates/syntax/src/parser/statement.rs`, `Keyword::Class => return self.refuse("class", 8)` in the statement dispatch; `crates/syntax/src/parser/expression.rs`, `primary_kind`, the arm `Keyword::Class => return self.refuse("class", 8)`, the line before the arm `Keyword::Super`; `Parser::held` exists and no construct holds one (its documentation in `parser/mod.rs`: "No construct holds one"); no function `hold` exists; the fixtures `crates/syntax/tests/sources/refused/class-declaration.js` and `class-expression.js` hold `class is not supported before slice 8` (and keep it, since the hold has the same text); `crates/syntax/tests/sources.rs`, `NESTING_KINDS: [&str; 61]`; `FunctionKind` (`crates/syntax/src/ast.rs`) ends with `Arrow`. Six places in `crates` hold `"class", 8` or `class is not supported`: the two refusals, the two fixtures and `crates/swell/tests/dynamic_function.rs` (`async_function_constructor_is_refused_by_the_hook_of_compile_strings` and `async_generator_function_constructor_is_refused_by_the_hook_of_compile_strings`), which still pass after this story (the hold has the text) and are rewritten by `story:class-definition-evaluation`. ## What later stories reuse

`crates/syntax/src/parser/class.rs` (new) and the tree: `Stmt::Class`, `Expr::Class` and the `Class` record of item 1 whole (the BindingIdentifier, the heritage, the constructor, the elements in source order, the span; an element is static or not and one of a method with its kind method, getter or setter, a field with its key and initializer, a static block; a key is literal, computed or private), so later stories fill the parse of kinds that exist and add no type; `FunctionKind::{ClassConstructor, FieldInitializer, StaticBlock}`; the default constructor, a `Function` of kind `ClassConstructor` spanning the class, numbered at the class's `{`; `Parser::hold`. `story:class-element-syntax-and-early-errors` parses fields, static blocks and private names into the record; `story:class-definition-evaluation` compiles it and lifts the hold `class`; `story:derived-classes-and-super-call` lifts `class heritage`.

## Domain relations

## Change

Failing tests first: the fixtures and tests below are written before the code and fail on the base.

- `crates/syntax/src/parser/class.rs` (new; its `mod` line in `parser/mod.rs` after `mod expression;`): a class declaration where a declaration stands (not as the body of `if`, a loop or a label: the grammar error), a class expression as a primary expression (the statement dispatch's arm `Keyword::Class` and the arm `Keyword::Class` of `primary_kind` call it, each replacing its `refuse`); the heritage as a LeftHandSideExpression; the elements: methods, getters, setters, generator, async and async generator methods, each optionally `static`, with a literal, string, number or computed key, parsed through `method_head`, `property_key` and `accessor_kind` of `parser/expression.rs` (called, not edited) with the class body's context (strict; `yield` and `await` as the code around gives them to computed keys); `;` elements. When the body has no `constructor`, the parser makes the default one: a `Function` of kind `ClassConstructor` with no parameter and an empty body, numbered at the class's `{`, spanning the class. The written constructor's function has kind `ClassConstructor` too and the class's span as its source text. A field (a key not followed by `(`) and `static {` are refused at their token as Context says. The class body is strict code from `class` to its `}`, the heritage too.
- The tree (`crates/syntax/src/ast.rs`): `Stmt::Class` inserted after `Stmt::FunctionDeclaration`, `Expr::Class` inserted after `Expr::Function(FunctionId)`, the `Class` record with `ClassElement` and `ClassKey` beside them, and the three kinds inserted after `Arrow` in `FunctionKind`.
