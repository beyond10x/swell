## Held sources

The one form every story of slice 8 uses for a source that holds a construct (decision A of the coordinator's revision 2). The fixture tests of `crates/syntax/tests/sources.rs` know `parses` (`valid/`), a SyntaxError (`early-errors/`) and a refusal (`refused/`); a source with a held construct fits none of them for long, because `Parser::held` answers the first hold of a source (the documentation of the field `held` in `parser/mod.rs`: "at the first token of the first such construct of the source") and that answer changes when another story lifts a hold. This form is built as follows, and every later story of the slice uses it.

1. The list of holds. `pub const HOLDS: &[(&str, u32)]` in `crates/syntax/src/parser/mod.rs`, inserted after `struct Parsed`, with its documentation; `parser` is a private module, so `crates/syntax/src/lib.rs` re-exports it (`pub use parser::HOLDS;`, inserted after `pub use ledger::{Ledger, Stop, Unlimited};`). One line per construct a `hold` call holds: the construct and its slice, in the order the stories add them. This story writes two lines, `("class", 8),` and `("class heritage", 8),`; `story:class-element-syntax-and-early-errors` appends five after them. The documentation of `Parser::hold` and of the field `held` point to it. A story that lifts a hold deletes its `hold` call and its line of `HOLDS` in the same change: that line is the site of the lift each lifting story names. Where two stories of one order delete adjacent lines, the second to merge gets a conflict there, and the fix is "keep both deletions".
2. The held sources. A source that holds a construct lives in `crates/syntax/tests/sources/held/` (new) from the story that adds its grammar to the close and after it; no story moves it or edits its header when a hold is lifted. Its header is `// <anchor>: held "<construct>", "<construct>", ...`: every held construct of the source, in the order of the first token of each in the source, which is the order `Parser::held` answers them (it keeps the first `hold` of a parse, and the parse reads the source in order). A held source holds no construct the parser refuses at its token (`super`, `new.target` and the others of `refused/`): such a refusal ends the parse before any hold is answered.
3. The test. `held_sources_answer_their_first_construct_still_held` (new, in `sources.rs`, inserted after `refused_sources_name_their_slice`) reads `held/`. The first construct of a header that is a line of `swell_syntax::HOLDS` is the one still held, and the source, as written and with a `"use strict";` prologue, answers exactly `<construct> is not supported before slice <n>` (n from that line), which `message_kind` reads as a refusal of slice n. When no construct of the header is a line of `HOLDS`, the source parses in both modes as a source under `valid/` does (the checks of `valid_sources_parse_in_both_modes` move into a function both tests call). Every line of `HOLDS` is named by at least one header, so a hold without a held source fails the test. Which construct is still held is read from the parser's constant, never from the fixture.
4. The compiler. `compile::held_sources_compile_once_nothing_in_them_is_held` (new, in `crates/compiler/tests/compile.rs`) reads the same directory (`../syntax/tests/sources/held` from the crate's manifest directory): a source with a construct still held answers that refusal and is never compiled; every other source compiles. So no source reaches a `CompileError::Tree` arm of a held kind, and the story that lifts a hold is the one whose sources must then compile.
5. The stack bound. The parser recurses to the full depth before it answers a hold (`analyse_parsed` in `lib.rs` answers `held` after the early errors), and `admitted` (`sources.rs`) answers `None` for every error but the nesting error, so a nesting kind whose source holds a construct fails `fits_the_stack_bound` at the depth that parses. With this story `admitted` also answers `Some(true)` when the one error is the refusal of a line of `HOLDS`: the parse and the early errors reached the end of the source. The scope analysis (`scope::analyse`, `scope.rs`), which a held source does not reach, is reached at the bound's depth by a kind from the story that lifts its last hold, and that story owns it: a failure of `fits_the_stack_bound` there is fixed in that story's `scope.rs` (a refusal at the depth the parser's bound gives, no recursion without a bound), reported with the kind and the depth. By `HOLDS` and the four new kinds: `class { [class { [ ... ] () {} }] () {} }` (this story; holds `class`) by `story:class-definition-evaluation`; `class extends (class extends ... {}) {}` (this story; `class`, `class heritage`) by `story:derived-classes-and-super-call`; `class { x = class { x = ... } }` and `class { static { class { static { ... } } } }` (`story:class-element-syntax-and-early-errors`; `class`, then `class field` or `class static block`) by `story:public-class-fields` and `story:class-static-blocks`. The 61 kinds of the base hold no construct. `admitted_by_the_parser` is unchanged: its `)` is a grammar error, which ends the parse before a hold is answered.
