## Context

Slice 11 brings modules (`epic:slice-11-modules`; `docs/design/engine.md`, section 12, item 11; governing decisions 9, 10, 11, 3 and 13). This story makes module records and their loading: `Agent::parse_module`, `load_requested_modules` and `finish_loading_imported_module` of `docs/design/host-interface.md` section 9 ("Modules, and the load hand-over", line 885 on the base), with the `LoadRequest` token, and the runner's module runs up to the end of loading. On the base (`f962c324`) the host interface declares the types and no entry point: `pub struct Module(Root)` with `#[expect(dead_code, reason = "modules: slice 11")]` (`crates/swell/src/value.rs` line 102), `ModuleRef` (line 118), `Referrer`, `ImportAttribute` and `LoadRequest` (`crates/swell/src/host/hooks.rs` lines 53 to 114; line 70: "the referrer and of the payload come with slice 11"), `SUPPORTED_IMPORT_ATTRIBUTES` defaulting to `&[]` (line 176), `HostError::ModuleStatus`, `ModuleTerminated`, `EvaluationInProgress` and `ModuleStatus` (`crates/swell/src/host/outcome.rs` lines 63 to 84). The heap has no arena of modules (`crates/swell/src/heap/mod.rs` lines 306 to 313: strings, symbols, private names, objects, realms, environments, scripts). The runner fails every module run at once (`crates/test262/src/run.rs` lines 238 to 241, "a module run is not made before slice 11"), and its host keeps no load request (`crates/test262/src/host.rs` line 101).

The count. 193 cases (193 runs) are this story's (`docs/plan/slice-11/story-module-records-loading-and-module-runs.cases.txt`): every one has the flag `module` and a parse `SyntaxError` as its `negative` (180 under `language/module-code/` and `language/import/`, `export/`; 13 that use `import()` or `import.meta` in a module), and every one fails on the base on "a module run is not made before slice 11". They pass once the runner parses the case as a module and judges the parse; the grammar and early errors are `story:module-syntax-and-early-errors`'s and `story:import-call-and-import-meta-syntax`'s. Loading is shown by the tests of the host interface (13 requirements) and by the runner's own fixture tree; the cases that load and run a module graph need linking and are `story:module-linking-and-evaluation`'s.

Design it follows: `host-interface.md` section 9 (the `LoadRequest` token, neither `Clone` nor `Copy`; `parse_module`, `load_requested_modules`, `finish_loading_imported_module`, `module_host_defined`, `requested_modules`; `FinishError` and `FinishErrorKind`; parse, finish and the reads also on `HookCx` and `Cx` by decision 5's rule; "A dropped `LoadRequest` releases its roots at the next safe point"), decisions 6 (misuse), 10 (a termination of loading, HOST-76) and 13 (`module_status`, the reads); ECMA-262 16.2.1.6.1.1 (`#sec-LoadRequestedModules`, `#sec-InnerModuleLoading`, `#sec-ContinueModuleLoading`, `#sec-FinishLoadingImportedModule`, the GraphLoadingState Record); `engine.md` decision 11, the bullets "Modules" (line 3561: "A loader over the case's directory: `./name` is the file beside the case, `.json` is a JSON module; `_FIXTURE` files are loaded only as dependencies") and "`negative`".

The design has no text yet on how the engine stores and walks modules: `engine.md` decisions 3 ("Execution model") and 4 ("Values and the heap") say nothing of a module record, and the host interface's section 9 states the surface only. This story does not start before the design author has added a paragraph "Modules" to `engine.md` (decisions 3 and 4) that settles at least: where a module record lives (the default this decomposition proposes: a new arena `modules` beside `scripts`, with its item kind in the collector and its entry in `KIND_SITES`); how the walks of the draft that recurse (InnerModuleLoading here; InnerModuleLinking, InnerModuleEvaluation and ResolveExport in the next story) run without the Rust stack growing with the graph (default: an explicit work stack in the agent, charged to the memory budget); and what a walk charges (default: one step per module visited and one per request read, as one step per entry of the microtask checkpoint). The text of this story follows those defaults; where the paragraph differs, the paragraph wins and the unit says which sentence it replaced.

## What later stories reuse

The module record, declared whole in this story with every field of a Cyclic Module Record and a Source Text Module Record (`#sec-cyclic-module-records` Table 46, `#sec-source-text-module-records` Table 49): its realm, environment (empty until linking), namespace (empty until the first GetModuleNamespace), [[Status]], [[EvaluationError]], [[DFSIndex]] and [[DFSAncestorIndex]], [[RequestedModules]] and [[LoadedModules]], [[CycleRoot]], [[HasTLA]], [[AsyncEvaluationOrder]], [[TopLevelCapability]], [[AsyncParentModules]], [[PendingAsyncDependencies]], [[HostDefined]], the `import.meta` object (empty until its first evaluation), the entries and the compiled code, the flag `module_terminated`, and a kind (source text, or synthetic with its default export for a JSON module), so that no story of order 5 adds a field: `story:module-linking-and-evaluation` fills the link and evaluation fields, `story:module-namespace-objects` the namespace, `story:top-level-await` the async fields, `story:import-meta` the `import.meta` object and `story:json-modules` the synthetic kind. Also: the arena and its trace, the entry points of loading, the `LoadRequest` roots, and the runner's loader and module run.

## Domain relations

- Module → Realm: many to one, references, set at `parse_module` and never changed — inferable (`spec/domains/host.yaml`, entity `swell.host.Module`, relation `realm`, `references`, cardinality one, via `realm_id`).
- Module load (a `LoadRequest` the host holds) → its referring module: many to one, references; the load lives from the hook call until `finish_loading_imported_module` consumes it or the host drops it — inferable (`spec/domains/host.yaml`, entity `swell.host.ModuleLoad`, relation `referrer_module`, and its lifecycle `Requested` → `Finished` | `Failed`).
- Module → the module loaded for each of its requests ([[LoadedModules]]): one to many, set once per (request, attributes) and never replaced (HOST-63: the referrer keeps its first module) — inferable (inferred from ECMA-262 `#sec-FinishLoadingImportedModule` step 1, and `docs/design/host-interface.md` line 965, HOST-63; no ess/1 document declares it: `swell.host.Module` has no relation to another module).
- Module → its [[HostDefined]]: one to zero or one, the host's value, the same `Rc` the host gave — inferable (inferred from `host-interface.md` line 883, HOST-55, and `crates/swell/src/script.rs` line 101, the script's; the model marks it `UNMAPPED`, `spec/domains/host.yaml` line 761).
