## Context

What remains of `Function` after slice 2 (`docs/design/engine.md`, section 12, item 3): `Function.prototype.apply` and `Function.prototype.toString` with HostHasSourceTextAvailable (`HOST-120`). The base has `bind`, `call`, `[@@hasInstance]` and the constructor (`crates/swell/src/builtins/function.rs`).

`Function.prototype.toString` returns the [[SourceText]] of an ECMAScript function (`sec-function.prototype.tostring`), and the engine keeps none: `ast::Function` has a `span` in code units (`crates/syntax/src/ast.rs`, line 416), `FunctionTemplate` (`crates/compiler/src/bytecode.rs`, line 517) has no field for it, and the UTF-16 copy of a source is dropped and credited when its parse ends (`crates/swell/src/script.rs`, module comment; `charged_source` and `credit_source` in `crates/swell/src/dynamic_code.rs`). So this story carries the text from the parser to the function object, through three crates.

Measured on the base (`309b850`, the run lines of `slot task test262` on it): `test/built-ins/Function/prototype/apply/` holds 46 cases of slice 3, 42 failing; `toString/` 45, 39 failing. 35 of those 39 end before the case starts, in `nativeFunctionMatcher.js` at the refusal of `const` (`awk -F'\t' '$2 == "03" && $6 ~ /^nativeFunctionMatcher.js/ { c[$3] = 1 } END { for (k in c) n++; print n }' .out/test262-base/runs.tsv` prints `35` on the base); by the scan they need slices 6 (16), 7 (2) and 8 (17) and move at the close. Four failing `toString` cases stay (the `TypeError` for a this value that is not callable). test262 therefore holds the text `toString` returns by no case of slice 3: the tests of this story hold it, and the 35 cases hold it again when slice 6 parses their harness file. The static scan of the failing cases of the slice (the decomposition read each case and the harness files it includes for the names of the builtins missing on the base and of the parts of later slices) finds 64 failing cases that name `apply` or lie in the two directories, name no builtin of another story of the wave and no part of a later slice: the list `docs/plan/slice-03/story-function.cases.txt` (64 lines: `apply/` 39, `toString/` 4, `test/language/function-code/` 20, the cases slice 2 moved here for `apply`, and one of `built-ins/Object`). A failing case that names builtins of two stories of the wave is on `docs/plan/slice-03/cross-story.tsv` and on no list, and one that needs a later slice is on `docs/plan/slice-03/move-estimate.tsv`; the ten lists, 4,050 cases, were read against the scan again when this plan was revised, and no case of a list names a builtin of another story. That list is this story's bound; a case of it that ends on a part outside this story is reported with that part and the coordinator takes it off the list in the wave record. One case that passes on the base stops passing with this story and cannot be kept: `Function/prototype/apply/this-not-callable.js`. Its fourth assertion is `assert.throws(TypeError, function() { Function.prototype.apply.call(/re/, {}, []); })`. On the base the member `Function.prototype.apply.call` throws the `TypeError` before an argument is evaluated, since `apply` is missing; with `apply` the argument `/re/` is evaluated first, the engine raises the counted refusal of slice 5 (`regular expression literal is not supported before slice 5`, `crates/syntax/src/error.rs`, line 26), and the runner fails every run in which the count of refusals moved (`docs/design/host-interface.md`, decision 13). No value this story could give the literal is right without the regular expression objects of slice 5, so the case is not on the list; `story:slice-03-conformance-close` moves it to slice 5 under its rule for a case that passed on the base of the wave and ends on a counted refusal after it, with the literal as its evidence, and lists it for a person to read. Three more cases of `apply/` are on `docs/plan/slice-03/move-estimate.tsv` and not on the list: `argarray-not-object.js` and `argarray-not-object-realm.js` call `Symbol()` inside `assert.throws` and end on `Expected a TypeError but got a ReferenceError` until slice 6, and `this-not-callable-realm.js` holds a regular expression literal (slice 5).

Design it builds on: a precondition that holds before the wave (the design author's change of 2026-11-21): `docs/design/engine.md`, decision 4, "Source text.". The source text of a script, of eval code and of a dynamic function stays alive as long as a function made from it and is charged to the memory budget with the compiled code, when the parse and compile step that made the code ends, at least one byte per code unit. It is kept with the compiled code, which lives while the host holds the script, while that code runs, and while a function object made from it is reachable; "the sweep that frees the compiled code credits it back with the code, never earlier". It is kept whatever HostHasSourceTextAvailable answers.
