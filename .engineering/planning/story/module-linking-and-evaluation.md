## Context

Slice 11 brings modules (`epic:slice-11-modules`; `docs/design/engine.md`, section 12, item 11). This story links and evaluates a module graph whose modules have no top-level `await`: `Agent::link` and `Agent::evaluate_module` of `docs/design/host-interface.md` section 9, and the runner's module run to its end. It builds on the records, loading, the ScriptOrModule component of two kinds and the runner's loader of `story:module-records-loading-and-module-runs`, after which a module case that is not a parse negative ends failed with the cause `a module run is not linked before story:module-linking-and-evaluation`.

The count. 122 cases (122 runs, every one a module run) are this story's (`docs/plan/slice-11/story-module-linking-and-evaluation.cases.txt`): 89 that link and run, 29 whose `negative` is a `resolution` `SyntaxError` (an import of a name the target does not export, an ambiguous star export, a cycle of indirect exports: `#sec-resolveexport`, `#sec-source-text-module-record-initialize-environment` step 7), and 4 with a `runtime` negative (`Test262Error` 2, `TypeError` 1, `ReferenceError` 1: an import binding read before its initialization). Every one fails on the base on "a module run is not made before slice 11". The cases with a namespace import, top-level `await`, `import.meta`, a JSON module or `import()` are the lists of orders 5 and 6.

How a name reaches its binding today, and why an import slot must read through (Q2, decided): the compiler resolves a name it can see to a slot (`GetLocal`, `GetEnv { hops, slot }`, `crates/compiler/src/bytecode.rs` lines 116 and 120, and their checked and set forms), but code compiled for a direct `eval` looks up by name at run time every name the eval code does not bind (`crates/compiler/src/resolve.rs` lines 48 and 49: "in eval code, a reference that the eval code does not bind is looked up by name"), through `Agent::resolve_name` (`crates/swell/src/env/mod.rs` line 640) and the slot names of each record (`SlotNames::find`, line 117); so an import binding cannot be a copy made at InitializeEnvironment: every read, by slot or by name, follows the import slot to the target module's binding at the time of the read.

Design it follows: `host-interface.md` section 9 (`link`, `evaluate_module`), decision 10 (a termination of linking leaves the graph `Unlinked`, HOST-75; of evaluation leaves each evaluating module at `Evaluating` with `module_terminated`, HOST-74; a broken invariant inside `parse_module` or `link`, HOST-157), decision 13 (`module_status`), decision 1 (`HookCx` has no call that evaluates a module, HOST-150); ECMA-262 16.2.1.6 (`#sec-moduledeclarationlinking`, `#sec-InnerModuleLinking`, `#sec-moduleevaluation`, `#sec-innermoduleevaluation`, `#sec-resolveexport`, `#sec-getexportednames`, `#sec-source-text-module-record-initialize-environment`, `#sec-source-text-module-record-execute-module`, `#sec-module-environment-records`); `engine.md` decision 11, "`negative`" (`resolution`: "module loading or linking must fail with it"); and the paragraphs `**Modules.**` and `**Module records.**` of `engine.md` (`story:modules-design-text`): the explicit work stacks and the charge of each walk (Q3, Q4), the module body's own frame (Q5), the import slot kind (Q2).

## What later stories reuse

Link and evaluation over `LinkState` (`crates/swell/src/module/link.rs`); ResolveExport and GetExportedNames, which `story:module-namespace-objects` calls and `story:json-modules` answers for the synthetic kind; InnerModuleEvaluation (`crates/swell/src/module/evaluate.rs`) with the async part left at its sync values ([[HasTLA]] false, [[AsyncEvaluationOrder]] unset, read from the `AsyncState` the records story made empty), which `story:top-level-await` completes; the module body's frame, whose ScriptOrModule component is the module; the import slot kind; the runner's judgement of `resolution` and `runtime` for a module run, which every later story's cases use.

## Domain relations

- Module → its environment: one to one, owned, made by InitializeEnvironment at `link` and kept for the module's life — inferable (inferred from ECMA-262 `#sec-source-text-module-record-initialize-environment` and `#sec-cyclic-module-records`, field [[Environment]]; no ess/1 document declares it: `swell.host.Module` in `spec/domains/host.yaml` holds no environment).
- Module → [[CycleRoot]]: many to one, a module of the same strongly connected component, set at evaluation — inferable (inferred from `#sec-innermoduleevaluation` step 16; no ess/1 document declares it).
- Module status: the lifecycle `New` → `Unlinked` → `Linked` → `Evaluated` of `swell.host.Module` (`spec/domains/host.yaml`, transitions `load`, `link`, `evaluate`); the states `linking` and `evaluating` are `UNMAPPED` there (line 237: they hold only inside one call), and the engine's `ModuleStatus` (`crates/swell/src/host/outcome.rs` line 84) has them.
