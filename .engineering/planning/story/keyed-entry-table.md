## Context

Slice 9 brings `Map`, `Set`, `WeakMap`, `WeakSet`, `Proxy` and `Reflect` (`epic:slice-09-collections-proxy-reflect`; `docs/design/engine.md`, section 12, item 9). `Map` and `Set` keep their entries in insertion order, find a key in constant time on average, keep an iterator that is in the middle of the entries working while entries are added, deleted and cleared (`#sec-map.prototype.foreach` and `#sec-createmapiterator`: an entry added before the iterator reaches its position is visited, a deleted one is not), and compare keys by SameValueZero (`#sec-samevaluezero`: `-0` and `+0` are one key, `NaN` is one key, two Strings with the same code units are one key). The engine has the keyed hash map (`crates/swell/src/heap/map.rs`, `KeyedMap`, SipHash keyed by `Seeds::hash_key`, HOST-145) and an ordered list with an index map above `SMALL` entries for properties (`crates/swell/src/object/property.rs`, `KeyedList`, line 188), but no table of entries keyed by a value. This story builds that table, in the engine and with its own unit tests, so that `story:map-and-set` builds the two builtins on it and `story:set-methods` and `story:map-upsert-and-group-by` reuse it. It is in order 1 and depends on no story; it has no case of test262 (every case reads `Map` or `Set`, which this story does not define).

The epic's open question "Where the SipHash and the host-seeded key first exist" is settled on the base (`62c7cf59`): `heap/map.rs` and `Seeds::hash_key` (HOST-145, delivered); this story uses that hasher (`Heap::hasher`) and adds none.

Design it builds on, by name: `docs/design/engine.md` decision 4 ("Objects": an ordered list with an index map above a small size; "Memory budget": every growth charged before it happens; "Collector": the collector allocates nothing) and decision 3 ("The step budget"); `docs/design/host-interface.md` decision 3 (HOST-145: no order the script can observe comes from a hash map) and HOST-25 and HOST-214 (`[slice 9]`, which `story:map-and-set` moves with this table under it). How the table holds a String key is not stated by the design; this story takes the default of question D1 of the decomposition (below, "Change").

## What later stories reuse

`EntryTable` with its cursors: `story:map-and-set` (the [[MapData]] and [[SetData]] of each object and the iterators), `story:set-methods` (the loops of `union` to `isDisjointFrom` over a table and its cursor) and `story:map-upsert-and-group-by` (`getOrInsert`, `getOrInsertComputed` and the groups of `Map.groupBy`). `story:weak-map-and-weak-set` does not use it (its tables are keyed by an object or a symbol without order).

## Domain relations

- A table → its entries: one to many, ordered by insertion, each entry a key and (for a map) a value, a deleted entry a hole until compaction — inferable (inferred from ECMA-262 `#sec-map-objects` and `#sec-set-objects`, where [[MapData]] and [[SetData]] are Lists of records whose deleted elements become `empty`; no ess/1 document declares it: the host model `spec/domains/host.yaml` holds no engine value, and ESS does not restate the slots of ECMA-262, `AGENTS.md`, "Rules").
- A table → its cursors: one to many, each cursor a position in the entries that compaction and `clear` move — inferable (inferred from `#sec-map.prototype.foreach`, note 1, and `#sec-%mapiteratorprototype%.next`; no ess/1 document declares it, for the same reason).

## Change

Failing tests first: the unit tests below are written before the code and fail to compile on the base (the module does not exist).

- `crates/swell/src/object/keyed_entries.rs` (new; its `mod` line in `crates/swell/src/object/mod.rs`): `EntryTable`, the List of [[MapData]] and [[SetData]]: a `Vec` of entries in insertion order (key, value; a hole after a deletion), and above `SMALL` live entries (`object/property.rs` line 188, the same bound and the same reason) a `KeyedMap` (`heap/map.rs`) from the canonical key to the position, made with `Heap::hasher` and charged by `KeyedMap::table_bytes_for` before it is made. The canonical key (`#sec-samevaluezero`, with `CanonicalizeKeyedCollectionKey`, `#sec-canonicalizekeyedcollectionkey`: `-0` becomes `+0`) is one word: an object, a symbol, a boolean, `undefined`, `null` by its handle or tag; a Number by its bits with every NaN one NaN and `-0` as `+0`; a String by the handle of its atom (decision D1, default A: a String key is interned once at insertion with the interning of `ops/conversion.rs` lines 344 to 390, so a lookup is one hash of one word and two equal Strings are one atom; an atom is held weakly by the atom table, and the table's `trace` lists the atom of each live key, so it stays while its entry does). A lookup by a String that is not interned yet interns it only when the operation inserts; `get`, `has` and `delete` look the atom up without making one, and a String with no atom is in no table.
- Operations, each `pub(crate)`: `find`, `insert` (appends or overwrites the value in place, the position unchanged), `delete` (makes a hole, the index map entry removed), `clear` (every entry a hole, as `#sec-map.prototype.clear` sets each to `empty`, then the storage dropped), `len` (live entries), `entry_at(position)` and `next_live(position)` for cursors. Compaction when at least half the entries are holes and no cursor would skip a live entry: positions of live entries move down, the index map is rebuilt or updated, and every registered cursor whose position is above a hole moves down by the holes before it (the `compacts` rule of `object/property.rs` line 343 is the model). A cursor is registered with the table (`open_cursor` answers its id, `close_cursor` drops it at the end of an iterator or a `forEach`), so a cursor's position is always the index of the next entry to visit after any operation; `clear` sets every cursor to the end of the empty storage, so an iterator that runs on after `clear` sees only entries added after it (`#sec-map.prototype.clear` with `#sec-%mapiteratorprototype%.next`).
- Bounds. Steps: every operation charges its steps before its work through the `Agent` that owns the heap (`Agent::charge_steps`): one for `find`, `insert` and `delete`, at most `SMALL` comparisons below the index map counted as that step (as `KeyedList`), and compaction one step per entry it moves; `clear` one step per 64 entries; a loop over the table (a cursor) one step per entry visited, charged by the caller. Memory: the entry storage and the index map grow by doubling and each growth is charged before it with `Agent::charge_bytes` (`object/mod.rs` line 515), and credited when it shrinks or the table is freed; a table made at the memory budget's last bytes ends the run with `Terminated(MemoryBudget)` and leaves the table as it was. Collector: `EntryTable::trace` lists every live key and value; it allocates nothing and visits each entry once (a worklist push per value, `heap/collect.rs`). Depth: no operation calls script (SameValueZero runs no code), so no re-entry and no frame is added. Run loop: nothing is added to `Agent::execute`.
- Tests, `#[cfg(test)] mod tests` in `object/keyed_entries.rs`, each run in both collection modes: `keys_compare_by_same_value_zero` (`-0` and `+0`, NaN of two bit patterns, two Strings made apart with the same code units, two objects); `insertion_order_survives_deletes_and_overwrites`; `a_cursor_visits_an_entry_added_before_it_and_skips_one_deleted_before_it`; `compaction_moves_every_cursor_to_the_same_next_entry` (1,000 entries, every second deleted, two cursors at different positions, compaction forced: each cursor's next entry is the same before and after); `clear_ends_every_cursor_and_entries_added_after_are_visited`; `the_index_map_is_made_above_small_and_charged` (`heap_bytes()` grows by at least `KeyedMap::table_bytes_for` at the `SMALL + 1`th insertion); `a_growth_over_the_memory_budget_ends_the_run_and_leaves_the_table` (a table filled until the budget ends it: `Terminated(MemoryBudget)`, `len` unchanged by the refused insertion); `a_loop_of_inserts_ends_at_the_step_budget` (`steps_per_entry` N: `Terminated(StepBudget)` with `last_entry_steps()` at most N); `a_string_key_keeps_its_atom_alive_across_collect` (a String made by concatenation, the only reference its entry: after `collect()` `find` with a String of the same code units answers the entry); `a_deleted_string_key_is_freed_by_collect` (the atom's slot free after `delete` and `collect()`); `the_order_does_not_depend_on_hash_key` (two heaps with different `hash_key`, the same 10,000 inserts and 5,000 deletes, the same sequence of keys by cursor). `object::generator::tests::a_generator_keeps_the_object_record_at_its_size` and `heap::collect` are run in both modes and pass as they are (no `ObjectKind` is added by this story).
