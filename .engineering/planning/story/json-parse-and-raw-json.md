## Context

`JSON` has `stringify` and its `@@toStringTag` since slice 1 (`crates/swell/src/builtins/json.rs`); this story completes clause 25.5 of the pinned draft: `JSON.parse` with its reviver and the source text it hands the reviver (25.5.2, the feature `json-parse-with-source`, which `conformance/test262/features.txt` runs), `JSON.rawJSON` (25.5.3), `JSON.isRawJSON` (25.5.1), and the step of SerializeJSONProperty that writes a raw JSON object as its text (25.5.4.2).

Measured on the base (`309b850`, the run lines of `slot task test262` on it): `test/built-ins/JSON/` holds 129 cases of slice 3, 81 failing (`parse` 65 of 65, `rawJSON` 8 of 8, `isRawJSON` 5 of 5, `stringify` 3 of 46). The static scan of the failing cases of the slice (the decomposition read each case and the harness files it includes for the names of the builtins missing on the base and of the parts of later slices) finds 67 failing cases that name a builtin of this story, no builtin of another story of the wave and no part of a later slice: the list `docs/plan/slice-03/story-json.cases.txt` (67 lines: `JSON/parse` 59, `JSON/rawJSON` 4, `JSON/isRawJSON` 3, one of `built-ins/Object`). A failing case that names builtins of two stories of the wave is on `docs/plan/slice-03/cross-story.tsv` and on no list, and one that needs a later slice is on `docs/plan/slice-03/move-estimate.tsv`; the ten lists, 4,050 cases, were read against the scan again when this plan was revised, and no case of a list names a builtin of another story. That list is this story's bound; a case of it that ends on a part outside this story is reported with that part and the coordinator takes it off the list in the wave record. Nine failing cases of the directory need slice 6 (arrow functions, `const`, `Symbol`) and move at the close. Outside the slice, `test/staging/sm/JSON/parse-mega-huge-array.js` (slice 19) has the most steps of the whole base run, 16,777,758, before it reaches the missing `JSON.parse`, and the `parse` cases of `test/staging/sm/JSON/` end on it too.

What the design asks of it: `JSON.parse` is "a loop with an explicit stack, bounded by the memory budget", charged "per node" (`docs/design/engine.md`, decision 3); the epic's acceptance 6: a text of 100,000 nested brackets ends in a result or in `Terminated(MemoryBudget)`, never in a Rust stack overflow. And what the wave plan hands the slice that completes `JSON` (`docs/plan/waves.md`, "What later slices take over"; `docs/plan/slice-02-run-loop-frame.md`): of the 11,100 bytes one re-entry takes on the worst path of the engine, through `toJSON` or a replacer, `json_serialize_property` is 2,080, `json_stringify` 1,632 and `json_property_list` 1,584; a change on that path has 1,560 bytes per re-entry before a stack test fails. This story changes `json_serialize_property` (the raw JSON step) and adds a second path of its own, the reviver.

Code it builds on, checked on the base and against `story:builtin-group-modules`: SetIntegrityLevel and TestIntegrityLevel are operations of `crates/swell/src/ops/objects.rs` after that story, complete and tested there (the mark of SetIntegrityLevel names this story and `story:object-integrity-and-prototype-methods`), and so is EnumerableOwnProperties, which the serialization calls with the kind key after that story and which the reviver calls the same way; this story writes none of the three. The serialization walks on an explicit stack of frames charged to the memory budget (`State`, `Frame`, `json_walk` in `builtins/json.rs`), which the parser and InternalizeJSONProperty follow; `StringBuilder` bounds every String built at run time; the slots of an ordinary object are `OrdinaryData` (`crates/swell/src/object/ordinary.rs`, line 22), where [[IsRawJSON]] goes as one more variant (the match over it in `builtin_tag` ends in a wildcard arm after `story:builtin-group-modules`); this story is the one writer of that file in the wave; `swell-num` reads a decimal literal (`crates/num/src/literal.rs`). No test or fixture of the repository relies on `JSON.parse` being absent.

## Change

Failing tests first: the tests below are written before the code and fail (`TypeError: the value is not a function`), and the 67 cases of the list fail on the base.

- `crates/swell/src/builtins/json.rs` becomes `crates/swell/src/builtins/json/mod.rs` (the object and `stringify`) with `crates/swell/src/builtins/json/parse.rs` (new):
  - `JSON.parse` (`sec-json.parse`) with ParseJSON, the JSON Parse Record, CreateJSONParseRecord, InternalizeJSONProperty, ShallowestContainedJSONValue and JSONArrayLiteralContentNodes (25.5.2.1 to 25.5.2.6 of the pinned draft, cited by their anchors): the text is read by a loop over an explicit stack, one entry per open array or object, each charged to the memory budget while it is open; a step per code unit read and per node made; a `SyntaxError` for a text that is not JSON (ECMA-404 as the draft cites it: no leading zero, no trailing comma, no single quote, no unescaped control character, the four white space code points only); a duplicate key keeps the last value, and `__proto__` is an own data property. With a reviver, the walk of InternalizeJSONProperty is a loop over a stack of its own (its keys come from EnumerableOwnProperties of `ops/objects.rs` or, for an Array, from its length), the holder, its keys and the parse records kept on the kept stack across every call; the reviver gets the context object with `source` for a primitive value whose value the walk has not seen changed, as the draft says.
  - `JSON.rawJSON` (`sec-json.rawjson`): an object with a null prototype, the property `rawJSON` and the slot [[IsRawJSON]], frozen by SetIntegrityLevel of `ops/objects.rs` (step 10 of the clause), for a text that is one JSON primitive value; `JSON.isRawJSON` (`sec-json.israwjson`). `isRawJSON`, `parse` and `rawJSON` are defined on `JSON` after the keys of the base, in the order of the clauses.
  - `stringify`: the step of SerializeJSONProperty for an object with [[IsRawJSON]]. The frames named in Context are measured before and after (bytes per re-entry through `toJSON` and through a replacer, as `docs/plan/slice-02-run-loop-frame.md` measured them); a frame that grows is taken apart here, in functions that return before the call into code.
- `crates/swell/src/object/ordinary.rs`: the slot [[IsRawJSON]] of an ordinary object, one variant of `OrdinaryData` (the enum at line 22) and what the compiler asks for it in that file.
- Marks: the one of SetIntegrityLevel in `crates/swell/src/ops/objects.rs` is removed, and nothing else changes in that file; `story:object-integrity-and-prototype-methods` deletes the same lines, and the merge takes the one change from both sides.
