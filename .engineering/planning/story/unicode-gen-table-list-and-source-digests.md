## Context

Slice 5 adds the tables of decision 8 (`docs/design/engine.md`) that `swell-unicode` does not have yet: today `swell-unicode-gen` (`crates/unicode-gen/src/main.rs`, 163 lines) writes one table, `crates/unicode/src/tables/zs.rs` (General_Category `Zs`, 7 ranges), from one data file, with the reading of that file, the merging of its ranges and the text of the table written for `Zs` alone. Six stories of the slice add tables to it: `story:case-mapping-tables-and-string-case-methods` (from `UnicodeData.txt` 1,505 code points with a simple uppercase mapping and 1,488 with a lowercase one, and the 119 lines of `SpecialCasing.txt`), `story:normalization-tables-normalize-and-locale-compare` (5,914 decompositions, 2,081 of them canonical, 968 code points with a combining class other than 0, 81 composition exclusions), `story:regexp-property-escapes-and-property-tables` (General_Category 30 values in 4,144 merged ranges, Script 174 values in 984, Script_Extensions 118 sets in 176, the 50 binary properties of ECMA-262's table that the data files hold in 11,869 merged ranges, `ID_Start` 684 and `ID_Continue` 799 among them, and the names of `PropertyAliases.txt` and `PropertyValueAliases.txt`), `story:regexp-case-insensitive-matching-and-modifiers` (the 1,512 lines of status `C` and `S` of `CaseFolding.txt`) and `story:regexp-v-flag-class-sets-and-properties-of-strings` (the 1,441 data lines of `emoji/emoji-sequences.txt` and 1,614 of `emoji/emoji-zwj-sequences.txt`); `story:identifiers-and-group-names-outside-ascii` reads `ID_Start` and `ID_Continue`. Counted on `98df839` from the vendored files with `awk` (merged ranges: adjacent ranges of one value joined), so a measure of the data, not of the tables the stories will write. This story makes the generator take a table as one entry of a list, as a line of a list file that the generator and its test both read, so each of them adds its lines to the list, its renderer and its own module, and nothing else of the generator or of its test; and it writes into every table the digest of its sources, as "Tests stay fast" names the form of a committed generated file. It adds no table and lifts no case.

Measured before this story on `98df839`: `target/debug/swell-unicode-gen --check` (the debug build `cargo build --locked -p swell-unicode-gen` makes, three runs under `time` of the shell) took 0.008 to 0.017 s of wall time and 0.00 s of CPU and printed `unicode-tables: 1 table(s) equal the generator output`. The gate runs it as `unicode-tables-check` (`taskfiles/unicode-tables.yml`) through `cargo run`, and decision 8 has the gate render every table in memory and compare it with the committed file.

Design it builds on: decision 8 (the vendored data under `data/unicode/17.0.0/` with `SOURCE`, the committed tables, the check in memory); decision 2 (`swell-unicode-gen` is a binary crate that nothing that ships depends on); no new design.

## Change

Failing tests first: the tests below are written before the code and fail on the base (the table has no digest line; the generator has no list).

- `crates/unicode-gen/src/ucd.rs` (new): the one reader the table `Zs` uses, moved out of `main.rs`: a file of lines `<code point or range> ; <value> [; ...] # ...` (the form of the derived files, `PropList.txt`, `Scripts.txt`, `ScriptExtensions.txt` and `emoji-data.txt`) read once per run to the merged inclusive ranges of each value asked for. It answers an error naming the file and the line for a line it cannot parse, and one naming the file for a file whose version is not that of the pin. The version of a file, by one rule that covers every vendored file the stories of the slice read (their first lines read on `8073b8e`), and written in `ucd.rs` as one function every reader calls: (a) a first line `# <name>-<version>.txt` gives it, and the version must be `17.0.0` (every file under `ucd/` but `UnicodeData.txt` and `ucd/emoji/emoji-data.txt`: the derived files, `PropList.txt`, `Scripts.txt`, `ScriptExtensions.txt`, `PropertyAliases.txt`, `PropertyValueAliases.txt`, `CaseFolding.txt`, `SpecialCasing.txt`, `CompositionExclusions.txt`, `DerivedNormalizationProps.txt`, `DerivedCoreProperties.txt`); (b) a first line `# <name>.txt` with no version, as the three emoji files have it (`ucd/emoji/emoji-data.txt`, read by `story:regexp-property-escapes-and-property-tables`, and `emoji/emoji-sequences.txt` and `emoji/emoji-zwj-sequences.txt`), gives it by the line `# Version: <major>.<minor>` of the comment block at the head of the file (line 8 of each), which must be `17.0`, and a head with neither line is an error; (c) a file with no comment line at its head (`UnicodeData.txt` alone, whose first line is a data line) is not checked by the reader: its version is the one `SOURCE` gives it (its address under `Public/17.0.0/`), and `unicode-data-check` holds the file against its digest there. No reader or writer without a caller in this story: the reader of `UnicodeData.txt` and the writer of pairs are written by `story:case-mapping-tables-and-string-case-methods`, the reader of a file of sequences and the writer of sequences by `story:regexp-v-flag-class-sets-and-properties-of-strings`, the first story that uses each (so this change is a refactor of what `Zs` runs, plus the list and the digest lines, with no `expect(dead_code)`).
- `crates/unicode-gen/src/render.rs` (new): the writer of a constant of sorted, disjoint inclusive ranges `&[(u32, u32)]`, moved out of `main.rs`, and the head of every table file: the line `// Generated by swell-unicode-gen from <sources> (Unicode 17.0.0); do not edit.` as `zs.rs` has it today, followed by one line per source `// Source: <path> sha256 <hex>`, the digest as `data/unicode/17.0.0/SOURCE` gives it for that path.
- The list: `crates/unicode-gen/tables.txt` (new), one line per table, its fields separated by one space: the path of the table under the root, the name of its renderer, and each source as a path under `data/unicode/17.0.0/`; its one line is `crates/unicode/src/tables/zs.rs zs ucd/extracted/DerivedGeneralCategory.txt`, and it has no comment line. `crates/unicode-gen/src/tables.rs` (new): the renderers by name, `zs` (moved out of `main.rs`) the first. `main.rs` reads `SOURCE` and the list under `--root` once, runs the renderer of each line, and writes or (with `--check`) compares; with `--check` it first compares the digest lines of each committed table with `SOURCE` and names a table whose digest differs before it renders anything, then renders every table in memory and compares the text, as now, a table of the list with no committed file failing the check with its path; it prints `unicode-tables: <n> table(s) equal the generator output` with `<n>` the number of lines of the list. A source that `SOURCE` does not list, or a renderer name that `tables.rs` does not know, is an error naming the line of the list (exit 2).
- `crates/unicode/src/tables/zs.rs`: written again by the generator, with its source line (`ucd/extracted/DerivedGeneralCategory.txt`, `sha256 d62e5bab70ca74f0...`); its ranges do not change. `crates/unicode/src/tables/mod.rs` and `crates/unicode/src/lib.rs` do not change.
- Tests, all in `crates/unicode-gen/tests/check.rs`. The crate is a binary (decision 2) and its tests run the binary on the workspace or on a copy under `CARGO_TARGET_TMPDIR`; no test reaches its modules, so there is no `tests/ucd.rs`, no library target and no change of `crates/unicode-gen/Cargo.toml`. The file takes its count of tables and what it copies from the list, so that a later table story passes `cargo nextest run --locked -p swell-unicode-gen --test main` without writing it: `EQUAL` (line 13, `1 table(s)` written in today) is made from the number of lines of `crates/unicode-gen/tables.txt`, and a copy holds `SOURCE`, the list, and every source and table the list names (today `DATA` and `TABLE`, lines 11 and 12, copied at line 45, name `Zs` alone). The tests: `check_passes_on_the_committed_table` and `check_fails_on_a_changed_table` in that form (the change still made in `zs.rs`); `a_table_added_to_a_copy_of_the_list_is_written_and_checked` (the copy of the list gets the line `crates/unicode/src/tables/zs_second.rs zs ucd/extracted/DerivedGeneralCategory.txt`: `--check` exits 1 naming `zs_second.rs`, a run without `--check` writes it, and `--check` then exits 0 and prints `unicode-tables: 2 table(s) equal the generator output`); `each_table_names_the_sha256_of_each_source_as_source_gives_it`; `a_digest_line_that_differs_from_source_fails_the_check_naming_the_table`; `a_source_that_source_does_not_list_is_an_error`; `a_renderer_the_generator_does_not_know_is_an_error`; and the reader, through the binary on a copy: `a_line_it_cannot_parse_names_the_file_and_the_line` (one line of the copied `DerivedGeneralCategory.txt` made unreadable: exit 2, and the standard error names the file and the line number) and `a_file_of_another_version_is_an_error` (its first line changed to name `16.0.0`: exit 2 naming the file; its first line changed to `# DerivedGeneralCategory.txt` with a line `# Version: 16.0` at its head: exit 2 naming the file, and with `# Version: 17.0`: exit 0; with neither line: exit 2). The merging of ranges is held by `zs.rs`, whose 7 ranges do not change. `tests/main.rs` does not change (no new test file).
- Time ("Tests stay fast", the `AGENTS.md` of the folder that holds the repository, and `AGENTS.md`, "Commands and the gate"): a test is terminated at 60 s and counts as failed, and the gate fails when the wall time of its test steps passes 120 s. A test stays under 1.5 CPU seconds alone in the default mode of the gate, under 2 s with a collection at every safe point, and under 2.5 s at its full count (`SWELL_FULL_COUNTS=1`) in either mode, measured with its test binary run directly with `--exact <name> --test-threads 1` under `time` of the shell (user plus system); a language script stays under 0.5 CPU seconds per run. The unit times each test before it adds it and names in its report each one over 1 CPU second with its time; a product several tests share is built once inside one test function or is a committed file, never in a `static` (the steps run a process per test); no test makes a network request; the unit runs the test binaries of its own change, never the whole gate and never a whole-workspace test run. Builds and tests go through the pool: `cargo` is the shim of the pool, anything else that compiles or tests is prefixed `slot`, a pool job ends after 10 minutes unless it names its time (`slot --timeout 30m`, the most), and a script that measures or waits runs without the prefix. No Python in any tool, test or command. None of these tests is expected over 0.1 CPU seconds here. They run the generator over every table of the list and copy at most the 6 MB of `data/unicode/17.0.0/`, so their time grows with the list: each later table story times them with its tables in the same way and names in its report each one over 1 CPU second.

Each later table story times it in the same way before and after its own table and names the size of its table (ranges, pairs or sequences, and the bytes of the constant) in its report.

## Out of scope
