## Context

Slice 2 is measured by what stops each failing run first. The runner prints counts, and per run only the runs a budget ended or a panic ended (`crates/test262/src/count.rs`, `run_cases`); the cause of every run is already in `run::Ran::detail` (the parse error, the thrown error or the termination; for a negative case that passed, the error it passed with). The decomposition of slice 2 (2026-11-21) had to measure with a throwaway copy of the tree that printed that field, and the stories of the slice state their acceptance on such lines: no run of slice 2 may still fail on a construct or a builtin the story delivers, and the closing story derives its rule lines from them. So the runner prints them itself, into a file, so that the measurement is repeatable from the repository.

Measured on the base of the slice (`6319af2`) with that throwaway runner, release build, 4 workers: 85,556 run lines; slice 2 has 9,173 runs, 3,787 passed and 5,386 failed, and 3,120 of its 5,245 cases have a failed run, which matches the gate line `test262-slice 02 5245 9173 0 0 5245 2125 3120 0`.

`$262.evalScript` is the member of `$262` that slice 1 left to slice 2 (`crates/test262/src/host.rs`, module comment: "`evalScript` (2)"). test262 `INTERPRETING.md` ("Host-Defined Functions") gives its steps: ParseScript of the string in the current realm; if that answers a list of errors, return a throw completion of the first; otherwise return ScriptEvaluation of the script. Measured on the base: 32 run cases of the pinned checkout call it, 13 in slice 2, all under `test/language/global-code/`, 1 in slice 17 and 18 in slice 18 (`xargs grep -l evalScript` over the run cases, sliced by the run lines). One of the 13 passes today for the wrong reason: `script-decl-func-err-non-configurable.js` wraps each `$262.evalScript(...)` in `assert.throws(TypeError, ...)`, and calling the missing member throws a `TypeError` ("the value is not a function"); its checks that `x` is not defined hold because nothing ran. With the member it passes for its reason: CanDeclareGlobalFunction answers false and GlobalDeclarationInstantiation throws the `TypeError` (`crates/swell/src/script.rs:365`, inferred from the code, not run). Of the 13: `script-decl-func-dups.js` needs nothing else and passes; `script-decl-func-err-non-configurable.js` passes for its reason; 4 need `Object.preventExtensions` of slice 3 (`script-decl-func-err-non-extensible`, `script-decl-func`, `script-decl-var-err`, `script-decl-var`); 3 need `let` of slice 6 (`script-decl-lex-restricted-global`, `script-decl-lex-var-declared-via-eval`, `script-decl-lex-var`); 4 need `class` of slice 8 (`script-decl-lex-deletion`, `script-decl-lex-lex`, `script-decl-lex`, `script-decl-var-collision`). `story:slice-02-conformance-close` moves those 11.

It is written on the interface as it is: a host function gets `Cx`; `Cx::parse_script(realm, source, None)` answers `Parsed::Parsed(script)`, `Parsed::Errors` (roots of `SyntaxError` objects of the realm) or `Parsed::Terminated`, and `Cx::evaluate_script(script)` answers the completion value, as a re-entry counted against `reentry_depth` (`crates/swell/src/host/mod.rs`, `parse_script` and `evaluate_script`, cited). The current realm is the realm of the `evalScript` function object: each realm gets its own `evalScript`, made with `new_host_function` in that realm and holding as host data the index of its realm among the realms the host keeps, so that `cx.realm_ref` of that realm is the realm ParseScript runs in. Nothing in the engine changes.

A refusal of the parser or its nesting limit inside the string is a `SyntaxError` like an error of the grammar. Thrown to the case, it lets a case pass that expects a `SyntaxError` for something else: `script-decl-lex-var.js` expects one for `let` on a `var` and would get the refusal of `let`. The runner already fails a run whose harness file or case ends in a refusal or the nesting limit, whatever `negative` says (`crates/test262/src/run.rs`, module comment, cited); `evalScript` keeps that rule: it reads the kind of the first error with `swell_syntax::message_kind`, throws the error as the steps say, and for a refusal or the nesting limit marks the run, as `createRealm` marks a run that wants another realm. A marked run is counted failed, with the detail `evalScript: refused: <message>` or `evalScript: nesting: <message>`.

Wave 3 adds a second rule beside this one (`story:eval-and-function-constructor`, decided by the coordinator): the engine counts every refusal it raises, while parsing through any entry (`Cx::parse_script` of `evalScript` included) or while running (the regular expression literal), and the runner fails every run in which the count moved. The mark of `evalScript` stays then, both rules run: it also covers the nesting limit, which the count leaves out, and its detail names the message of the refusal, which the count does not carry; dropping its refusal half would only edit `crates/test262/src/host.rs` again in wave 3 for no change of outcome.

A run that `evalScript` marks for a refusal counts in `test262-refused`, as a refusal of the case's own source does (`Ran::refused` answers true for it); a run marked for the nesting limit fails but is not counted there, the nesting limit not being a refusal. The `test262-refused` line goes to standard error (`count.log`), not to `expected.txt`, so the gate does not compare it; the coordinator records its new number with the other numbers of the gate. Measured on the base (the throwaway runner's run lines, `awk` over `count.log`, and the cases read): this story alone raises it by 5 runs, those of the three cases of slice 2 whose first `evalScript` call holds a refused `let` and is reached: `script-decl-lex-deletion.js` (1 run, `noStrict`), `script-decl-lex-restricted-global.js` and `script-decl-lex-var.js` (2 runs each). The other 10 cases of slice 2 fail before their first call (their own `let` or `class` refused, `Object.preventExtensions` or `eval` missing) or call it with nothing refused; of the 19 cases of slices 17 and 18, 16 fail on the refusal of a harness file, 2 on the refusal of their own source and 1 on `eval is not defined`, all before any `evalScript` call. None of those 19 passes on the base (0 passed runs), and the one case of slice 2 that passes there, `script-decl-func-err-non-configurable.js`, keeps passing, so the comparison of the acceptance needs no allowed exception: no run passes on `main` only because the member is missing, other than that one, which passes for its reason afterwards.

Design changes this story waits for: none. `evalScript` is a member of `$262` (design, section 12, item 1 of "What each slice builds", and decision 11 of `docs/design/engine.md`); the runner file stays under `TEST262_OUT` with every other output of the task.

## Change

Failing tests first: the tests below are written before the code and fail (no option `--runs`; `$262.evalScript` is not a function).

- `crates/test262/src/count.rs`: `run_cases` gathers one line per run, in the order of the jobs: `test262-run<TAB><slice><TAB><path><TAB><strict|non-strict|module><TAB><Passed|Failed|Budget><TAB><detail>`, the detail with every tab and line end written as a space. Nothing else it prints changes.
- `crates/test262/src/main.rs`: an option `--runs <file>` of `count` writes those lines to `<file>`, not to standard output or standard error (85,556 lines would bury both). A file it cannot write is a command it cannot carry out: exit 2. With `--run none` the file is written and holds no line. The module documentation names the option and the line form.
- `taskfiles/test262.yml`: the task passes `--runs "$TEST262_OUT/runs.tsv"`, a file beside `lines.txt` and `count.log`, with no variable of its own; the summary of the task names it. Every run of the task writes the file of its own output directory: a planted run of the gate, which sets `TEST262_OUT` to a directory of its own and `TEST262_RUN=none` (`tests/gate/test262-refuses-a-count-that-differs-from-expected.sh:31`, cited), writes its own file and never empties `.out/test262/runs.tsv`. The later stories of the slice read `.out/test262/runs.tsv` after their own `slot task test262`, whose `TEST262_OUT` is the default `.out/test262`. The root `Taskfile.yml` does not change.
- `crates/test262/src/host.rs`: `$262.evalScript(sourceText)` as above: ToString of the argument through `cx.to_string`, its code units as `Source::Utf16`, `cx.parse_script` in the realm of the function, the first error thrown (`cx.get` of its root) and the run marked for a refusal or the nesting limit, `Parsed::Terminated` ended as the termination, then `cx.evaluate_script` and its completion. A host error on a handle the engine gave ends the run in `Terminated(EngineFault)` (`fault_on_host_error`, decision 6). The realms the host keeps hold the first realm of the run too. The module comment no longer lists `evalScript` among the members to come.
- `crates/test262/src/run.rs`: after the case, a run marked by `evalScript` ends failed with its detail, whatever the case and `negative` answered, read as `wanted_realm` is read; for a refusal `Ran::refused` answers true, so that `count.rs` counts the run in `test262-refused`, and for the nesting limit it does not; the module comment says so.
- `crates/test262/tests/run.rs`: `runs_file_has_one_line_per_run` (the fixture tree the file already counts: one line per run, six tab-separated fields, the slice and mode as the counted lines have them), `runs_file_names_the_refusal_and_the_thrown_error` (a run of the refused fixtures reads `parse: refused: SyntaxError: ... is not supported before slice <n>`, a case that throws reads `threw <Name>: <message>`), `runs_file_does_not_change_the_counted_lines` (standard output byte-equal with and without `--runs`), and over a new fixture tree `eval-script`: `eval_script_declares_in_the_global_scope`, `eval_script_throws_the_first_syntax_error`, `eval_script_answers_the_completion_value`, `a_refusal_inside_eval_script_fails_the_run` and `the_nesting_limit_inside_eval_script_fails_the_run` (each asserts its `test262 language/eval-script` count or its run line; the first also that the `test262-refused` line of the tree reads `test262-refused 2`, the two runs of `refusal-fails-the-run.js`, and not 4: the nesting case is not counted).
- `crates/test262/tests/fixtures/eval-script/`: `features.txt`, `harness/assert.js`, `harness/sta.js` (copies of the ones of the `refused` tree), `test/language/eval-script/declares-a-global.js`, `throws-the-syntax-error.js`, `answers-the-completion.js` (passing cases), `refusal-fails-the-run.js` (`assert.throws(SyntaxError, function () { $262.evalScript("let x;"); })`, counted failed) and `nesting-fails-the-run.js` (a string nested past the limit the test passes, counted failed); the fixture `design.md` gives `test/language/` to slice 2 already.
