## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8). This story runs a derived class: the heritage (the steps of ClassHeritage in `#sec-runtime-semantics-classdefinitionevaluation`: `null` gives a prototype without parent and `%Function.prototype%` as F's parent; a value that is no constructor, or whose `prototype` is neither an object nor `null`, throws a `TypeError`), the box's kind derived, the `this` of a derived constructor as a hidden binding (item 6 of "Classes"), SuperCall as four instructions with no re-entry (item 7), the derived return (item 8: `KeepThis`, the three states of the frame's `constructed`, the rule after the pop with both errors made in the caller's realm: by `return_from_frame` for a frame that is not the base of its run, by `construct_function` after `run_frame` for the base frame of a Rust entry, Change), the default derived constructor (a template with `SuperCallKept(0)`, no iterator read), `super` in an arrow function at run time and `super` in direct eval code (PerformEval's `inMethod` and `inDerivedConstructor`, `#sec-performeval`). It owns the flag that admits a SuperCall in the constructor of a class with a heritage (item 5, decision 6 of slice 8). Subclassing `Promise`, `Array`, `RegExp` and `Error` needs nothing more: those constructors make their object from NewTarget already.

It lifts the hold `class heritage is not supported before slice 8` (`story:class-syntax-and-early-errors`) and the refusals `super in an arrow function is not supported before slice 8` and `super in eval code is not supported before slice 8` (`story:super-property-and-super-syntax`). It reads the frame's `function` and NewTarget and the eval context of `story:new-target-meta-property`, the box and `push_construct_frame`'s NewTarget parameter of `story:class-definition-evaluation`, and the super instructions of `story:super-property-and-super-syntax`, which work in an arrow and in eval code as they are (they read `frame.function`). `Dup; InitInstance; Pop` after each SuperCall uses `story:class-definition-evaluation`'s instruction; the initializer it calls is empty until the element stories fill it, and the cases where fields and `super()` meet are on `story:class-static-blocks`' list (without a private field) and `story:private-fields-and-private-in`'s (with one), by the scan's rule.

Edges: `story:class-definition-evaluation` (and through it `story:new-target-meta-property`: both write `make_frame`, `construct_function` and `push_construct_frame` before this story), `story:super-property-and-super-syntax`, `story:class-element-syntax-and-early-errors` (its contexts of field initializers and static blocks, where a SuperCall stays an early error, and both write `parser/class.rs`, `parser/expression.rs`, `HOLDS` and `compiler/src/expression.rs`).
