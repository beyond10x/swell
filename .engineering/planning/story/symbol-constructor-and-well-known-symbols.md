It is the first story of the slice that needs slice 3 delivered (the order of the decomposition: `Symbol` as a builtin, the iterator prototypes and every story that reads them come after `story:slice-03-conformance-close`): its registration writes `crates/swell/src/builtins/mod.rs`, `crates/swell/src/realm/{intrinsics,global_object,mod}.rs` and `crates/swell/src/ops/conversion.rs`, which stories of slice 3 write, and many cases of its list read a builtin slice 3 delivers. It depends on `story:computed-names-and-object-spread` because its cases write symbol keys as computed property names (`{ [Symbol.toPrimitive]: ... }`: 24 cases of its list need a computed name, and the list's closure holds them), not for a file: the two share none. The first failing run of 425 cases of slice 6 ends on `threw ReferenceError: Symbol is not defined` (`awk -F'\t' '$2 == "06" && $5 != "Passed" && !($3 in s) { s[$3] = 1; if ($6 ~ /Symbol is not defined/) c++ } END { print c }' .out/test262/runs.tsv` prints `425`; 1,126 runs over all slices end on it).

What exists on the base: the `Symbol` handle of the `Value` enum and symbol keys (`crates/swell/src/value.rs`, lines 27 and 62; decision 4); the symbol arena with its [[Description]] (`crates/swell/src/heap/mod.rs`, `SymbolRecord`, line 34); seven of the thirteen well-known symbols of Table 1 (`crates/swell/src/realm/mod.rs`, `WellKnown`, line 33: `hasInstance`, `toPrimitive`, `toStringTag`, `species`, `unscopables`, `isConcatSpreadable`, `match`), read already by ToPrimitive, `instanceof`, `Object.prototype.toString`, `Array.prototype.concat`, ArraySpeciesCreate, `with` and IsRegExp. Design it builds on: `docs/design/engine.md`, decision 4, "Symbols" (lines 830 to 875, merged on `wave/s3-1`). The GlobalSymbolRegistry is the agent's, a part of the heap beside the atom table: a `KeyedMap` (`crates/swell/src/heap/map.rs` line 19, the heap's hasher, keyed by `hash_key` alone) from the code units of a key to its Symbol, whose [[Description]] is the key's String; the `SymbolRecord` of a registered Symbol says that it is registered, so `Symbol.keyFor` answers its description with no second map (items 1 and 2). The registry is a root of the collector at a root site of `crates/swell/src/heap/collect.rs`, every registered Symbol and its key live as long as the agent, and no entry is ever removed (item 2). `Symbol.for` of a new key charges the record, the map's copy of the units and the growth of its table (`KeyedMap::table_bytes_for`, line 95, before it grows), no sweep credits them, so a loop of `Symbol.for(String(i))` ends in `Terminated(MemoryBudget)` where the same loop over `Symbol(String(i))` keeps nothing past a collection; steps: the call's and one per code unit hashed and compared (item 3). A Symbol object keeps its Symbol in `OrdinaryData` (`crates/swell/src/object/ordinary.rs`), traced with the object, read by thisSymbolValue (item 4). The well-known symbols are agent values (`realm/mod.rs`), twelve in slice 6, none in the registry. The conversions of `ops/conversion.rs` are the one place a Symbol meets ToString or ToNumber (item 5).

## Domain relations

- Agent → GlobalSymbolRegistry entry, one-to-many, the agent owns them, each entry referencing one symbol and its key string and keeping both alive for the life of the agent — stated by `docs/design/engine.md`, "Symbols", item 2 (no ess/1 document declares this relation).
- Symbol wrapper object → its symbol, many-to-one, the object keeps the symbol alive — inferable (`#sec-symbol-objects`; inferred from `crates/swell/src/object/ordinary.rs`, `OrdinaryData`, line 23, where [[BooleanData]] and [[NumberData]] are kept; no ess/1 document declares it).
