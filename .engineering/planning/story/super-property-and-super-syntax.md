## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8). This story is the `super` keyword's grammar and SuperProperty: the grammar of SuperProperty (`super.name`, `super[expression]`) and SuperCall (`super(arguments)`, `#sec-super-keyword`), the early errors that forbid them outside a MethodDefinition (`#sec-function-definitions-static-semantics-early-errors`, `#sec-method-definitions-static-semantics-early-errors` HasDirectSuper, `#sec-scripts-static-semantics-early-errors`), and the evaluation of a SuperProperty (`#sec-super-keyword-runtime-semantics-evaluation`, MakeSuperPropertyReference, GetSuperBase `#sec-getsuperbase`; `delete super[...]` throws a `ReferenceError`). It owns the flag that makes `super.x` legal in every MethodDefinition, through `method_head`, for object literals and classes alike, the class constructor included (item 5 of "Classes", decision 6 of slice 8). It needs no other story of slice 8: order 1, built beside `story:new-target-meta-property` and `story:class-syntax-and-early-errors`.

`super` inside an arrow function where a method encloses it, and `super` directly in eval code, need the frame's `function` of `story:new-target-meta-property` (built at the same time) and PerformEval's `inMethod`: they are `story:derived-classes-and-super-call`'s, which lifts them. Until then this story refuses them at once with `super in an arrow function is not supported before slice 8` and `super in eval code is not supported before slice 8` (`refuse_at`, as `new_rest` refuses `new.target` today; no hold, so `Parser::hold` has one owner, `story:class-syntax-and-early-errors`). Their cases (`expressions/super/prop-{dot,expr}-{obj,cls}-val-from-arrow.js` and the cases of `super` in eval) are on that story's list. The early errors of `super` in an arrow at the top (`global-code/super-prop-arrow.js`, `async-arrow-function/early-errors-arrow-*-contains-super-*`) are this story's: an arrow takes the answer of the code around it.

On the base (the code of `62c7cf59`; the unit reads every named site again on its own base): the parser refuses `super` at once (`crates/syntax/src/parser/expression.rs`, `primary_kind`, the arm `Keyword::Super => return self.refuse("super", 8)`, the line after the arm `Keyword::Class`); the comment in `crates/syntax/src/early.rs` ("which the parser refuses before slice 8, in a method as anywhere") says `super` is refused; an object-literal method has its [[HomeObject]] (`EcmascriptFunction::home_object`, set by `make_method`). The refusal `super is not supported before slice 8` is part of section 12, item 8 (the entry "Each slice" of `docs/plan/waves.md`, checked); five places in `crates` hold its text: the arm of `primary_kind`, the fixture `crates/syntax/tests/sources/refused/super.js`, and the three tests that expect it, `crates/syntax/tests/sources.rs` (`yield_star_in_an_async_generator_parses_through_every_entry`, the entry `x = { m() { super.x; } }`), `crates/swell/tests/async_methods.rs` (`super_in_an_async_method_is_refused_as_in_a_plain_method`) and `crates/swell/tests/async_generator_methods.rs` (`an_async_generator_method_has_its_object_as_home_object`). Each of the three is rewritten here to the value the method now reads (or, in `sources.rs`, to an early error of `super` in a plain function).

The list is `docs/plan/slice-08/story-super.cases.txt`: the 66 cases of the key `super` of `docs/plan/slice-08/scan.tsv` (a SuperProperty or SuperCall outside a class, outside eval and outside an arrow in a method; 34 negative parse cases). By directory: `language/expressions/super` 18, `language/expressions/object` 16, the early errors of functions, async functions, async generators and async arrows 24, `language/global-code` 4, `language/computed-property-names/object` 3, `language/expressions/delete` 1. Their 128 runs fail on the plan's base run (the full run of 2026-11-26 on `149e12f1`, equal to `conformance/test262/expected.txt` on `62c7cf59`; slice 8: `test262-slice 08 9302 18455 0 0 9302 5 9297 0`), all on `super is not supported before slice 8`. `super.x` in a class method is on the list of `story:class-definition-evaluation`, which runs it through this story's instructions. A case of the list that ends on a part outside this story goes to `docs/plan/slice-08/close-later.tsv` by the coordinator's commit, as `story:new-target-meta-property` states.

## What later stories reuse

`Expr::SuperMember` and `Expr::SuperCall` and their parse; the flag that admits a SuperProperty, set by `method_head` (class methods and constructors included; `story:class-element-syntax-and-early-errors` sets it in field initializers and static blocks; `story:derived-classes-and-super-call` adds the flag of SuperCall and lifts the two refusals above); the super instructions, which read only `frame.function`'s `home_object` (class methods use them as they are; in a derived constructor the receiver is the checked `this` read of `story:derived-classes-and-super-call`).

## Change

Failing tests first: the tests and fixtures below are written before the code and fail on the base.

- Parser. `super` followed by `.` or `[` is `Expr::SuperMember` (a name or a computed key), followed by `(` is `Expr::SuperCall` (arguments as a call's): both inserted after the variant `Call` of `Expr` (`crates/syntax/src/ast.rs`), their arms after the arm `Expr::Call { .. } | Expr::OptionalCall { .. }` in `HeapBytes for Expr` and `Expr::children`; any other `super` is the grammar error `unexpected token super`. The arm `Keyword::Super` of `primary_kind` (`parser/expression.rs`) parses them. A SuperProperty stands where the nearest function that is not an arrow is a MethodDefinition: a field `super_property` of `Parser` (`parser/mod.rs`, inserted after the field `new_target` that `story:new-target-meta-property` adds after `outer_awaits`; on a base without it, after `outer_awaits`), saved and put back in `save_context`, `open_context` and `function_close` (`parser/function.rs`, one line each after the line of `new_target`, or of `awaits`), and set in `method_head` (`parser/expression.rs`), which every MethodDefinition passes, the class's too. Anywhere else a SuperProperty is an early error; a SuperCall is an early error everywhere this story parses. Each early error with the message of its rule (`early.rs`, beside the rule of `new.target`'s story; the comment above rewritten). `super` in an arrow where the flag admits it and `super` directly in eval code (the eval entry of `parser/mod.rs`) are refused at once with the two messages of Context. `super` as a whole is no assignment target; `super.x` and `super[k]` are (`++super.x`, `super[k] += 1`, `super.x ??= 1`).
- Compiler (`crates/compiler/src/{bytecode,disasm,expression,resolve}.rs`). A SuperProperty compiles to instructions inserted after the variant `DeleteIndex` of `Instruction`, each documented: `GetSuperNamed(k)`, `GetSuperIndex`, `PutSuperNamed(k)`, `PutSuperIndex`, `SuperKey` (the first steps of a compound assignment or update, as `PropertyKey` does) and `DeleteSuper` (evaluates the key expression, converts nothing, throws the `ReferenceError`). Order, as item 5 states: the receiver (`This`) is read first, then the key expression is evaluated, then the base (the [[GetPrototypeOf]] of `frame.function`'s `home_object`), then the key is converted (`prop-expr-getsuperbase-before-topropertykey-*`); a get and a set use the receiver; a call gets it as `this`; a failed set throws in strict code (`prop-*-obj-ref-strict.js`). The arms in `disasm.rs` for the two named forms go after `I::DeleteNamed(k)`; the others print through `other`. The arms in `expression.rs` and in the walk of `resolve.rs` (`expr`) go after the arm `Expr::Call { callee, arguments } | Expr::OptionalCall { .. }`. `Expr::SuperCall` gets its arm in every exhaustive match and answers `CompileError::Tree` (no source reaches it before `story:derived-classes-and-super-call`, which replaces that arm: every SuperCall is an early error here, a test says so). A compiler fixture pair `crates/compiler/tests/sources/super-property.{js,disasm}` (new).
- Run loop.
