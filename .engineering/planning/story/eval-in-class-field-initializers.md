## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8). This story is direct and indirect eval inside a field initializer: [[ClassFieldInitializerName]] of the initializer (`#sec-ecmascript-function-objects`, set by ClassFieldDefinitionEvaluation), PerformEval's `inClassFieldInitializer` (`#sec-performeval`: "If inClassFieldInitializer is true and ContainsArguments of body is true, throw a SyntaxError exception"), and the other three flags as they read for an initializer (`inFunction` and `inMethod` true, `inDerivedConstructor` false: `new.target` is undefined in the eval, a SuperProperty reaches the initializer's home object, a SuperCall is a SyntaxError), the eval's `this` the instance, its `var` declarations in the initializer's own variable environment. Order 5, after `story:instance-elements-initialization-order` (the initializers of base and derived classes in their final order, and through it the eval rules of `story:derived-classes-and-super-call` and the eval context of `story:new-target-meta-property`), built beside `story:private-fields-and-private-in`.

The list is `docs/plan/slice-08/story-eval-fields.cases.txt`: the 84 cases of the key `eval-fields` of `docs/plan/slice-08/scan.tsv` (a class with a public field whose initializer calls `eval`, and no private name; no negative case). By directory: `language/statements/class/elements` 42 and `language/expressions/class/elements` 42 (`*-direct-eval-err-contains-arguments`, `*-direct-eval-err-contains-supercall*`, `*-direct-eval-contains-superproperty-*`, `*-direct-eval-err-contains-newtarget`, their `indirect-eval` and `nested-*` variants, and `arrow-body-*-eval-*`). Their 164 runs fail on the plan's base run, all on `class is not supported before slice 8`. The base run of this plan is the full run of 2026-11-26 on `149e12f1` (slice 8: `test262-slice 08 9302 18455 0 0 9302 5 9297 0`). The same cases with private names are on the list of `story:private-names-in-eval-code`.

Design it builds on: design change 4 of this decomposition (eval in class bodies: PerformEval's flags read from the running frame's function or the function an arrow's `this` comes from; the slot [[ClassFieldInitializerName]] in the class constructor box of design change 1 or on the synthetic initializer, as that text decides), written by a design author before the units start. The unit reads the text that landed and follows it where it differs.

## Change

Failing tests first: the tests below are written before the code and fail on the base.

- `crates/syntax/src/lib.rs`, `parse_eval_with`: the rule of `inClassFieldInitializer` (`arguments` anywhere in the eval code outside a non-arrow function is the SyntaxError; `early.rs` gives ContainsArguments); the documentation of `parse_eval` names the rule beside the others.
- `crates/compiler/src/class.rs` and `crates/swell/src/interp/class.rs`: the initializer carries [[ClassFieldInitializerName]] (for the one synthetic initializer of a placement: the key of the field whose initializer is running, kept on the initializer's frame as design change 4 decides); `crates/swell/src/dynamic_code.rs`: `eval_code_of` and `parse_eval_code` compute `inClassFieldInitializer` from it, and `inFunction`, `inMethod`, `inDerivedConstructor` as they read for an initializer; an arrow in an initializer reads them through the function its `this` comes from.
- Tests, in `crates/swell/tests/class_field_eval.rs` (new; `tests/main.rs` generated by `sh taskfiles/test-main.sh write`), each in both collection modes: eval of `arguments` in an initializer (SyntaxError, direct; indirect eval reads the global `arguments` binding), in a function inside the eval (allowed), `eval("new.target")` (undefined), `eval("super.x")` (the home object's prototype), `eval("super()")` (SyntaxError, also in a derived class), `eval("this")`, a `var` declared by the eval visible to a later eval of the same initializer and not to the next field's; an initializer whose eval loops stopped by the step budget (`Termination::StepBudget`) and by an interrupt (`Termination::Interrupted`); nested eval in an initializer bounded by `eval_stack` and `frame_depth` (RangeError, not a panic).
- Time ("Tests stay fast", the `AGENTS.md` of the folder that holds the repository, and `AGENTS.md`, "Commands and the gate"): a test is terminated at 60 s and counts as failed, and the gate fails when the wall time of its test steps passes 120 s. A product several tests share is built once inside one test function or is a committed file, never per test; no test makes a network request or a model call; the unit runs the test binaries of its own change, never the whole gate (`slot task check`) and never a whole-workspace test run. Builds and tests go through the pool: `cargo` is the shim of the pool, anything else that compiles or tests is prefixed `slot`; a pool job ends after 10 minutes unless it names its time (`slot --timeout 30m` or `SLOT_TIMEOUT=30m`, 30 minutes at most); a script that measures or waits runs without the prefix.
