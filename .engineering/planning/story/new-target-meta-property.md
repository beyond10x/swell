## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8: classes, `super`, `new.target`, private names, static blocks). This story is `new.target` (`#sec-meta-properties`, NewTarget, `#sec-meta-properties-runtime-semantics-evaluation`, GetNewTarget `#sec-getnewtarget`) in every function that is not a class: its grammar and early errors, its value in a call (undefined) and in a [[Construct]] (the NewTarget the construct was given), in an arrow function (the `new.target` of the code that made it), in a generator and an async function (always undefined: neither is a constructor), and in direct eval code (allowed only where PerformEval's `inFunction` is true, `#sec-performeval`). It needs no other story of slice 8 and none of them comes before it: order 1, built beside `story:class-syntax-and-early-errors` and `story:super-property-and-super-syntax`.

It also brings the part of PerformEval that the later stories of the slice read: the four flags `inFunction`, `inMethod`, `inDerivedConstructor` and `inClassFieldInitializer` that PerformEval computes from the running function before it parses (`#sec-performeval`, the steps "Let inFunction be false ..." to "If classFieldInitializerName is not empty"), passed to the eval entry of `swell-syntax` as one value, and the function an arrow function takes its `this` from (GetThisEnvironment, `#sec-getthisenvironment`, skips arrow functions). This story reads `inFunction` only (the rule "If inFunction is false and body Contains NewTarget, throw a SyntaxError exception"). On its base every function gives `inMethod` from its [[HomeObject]] (object literal methods have one), and `inDerivedConstructor` and `inClassFieldInitializer` are false for every function the engine can make; `story:derived-classes-and-super-call` and `story:eval-in-class-field-initializers` add the rules that read them, and the class stories make the functions for which they are true. Each flag is computed as the clause states it, so none of them is a stand-in.

On the base (`62c7cf59`; the unit reads every place named here again on its own base): the parser refuses `new.target` at once (`crates/syntax/src/parser/expression.rs`, `new_rest`, line 865: `refuse_at("new.target", 8, ...)`), the frame has no [[NewTarget]] (`crates/swell/src/interp/frame.rs`, `Frame`: `this`, `function`, `constructed`, no new target), an arrow function keeps only its `this` (`EcmascriptFunction::lexical_this`, `crates/swell/src/object/ecmascript_function.rs` line 76; `keep_lexical_this`, line 638), and `swell_syntax::parse_eval_with` takes the source, `strict_caller` and the options (`crates/swell/src/dynamic_code.rs`, `parse_eval_code`, line 312). The refusal `new.target is not supported before slice 8` matches section 12, item 8 (the entry "Each slice" of `docs/plan/waves.md`, "What later slices take over", checked for this slice: the four refusals that name slice 8, `class`, `super`, `new.target` and `private name`, are all parts of item 8). The fixture `crates/syntax/tests/sources/refused/new-target.js` holds it.

The list is `docs/plan/slice-08/story-new-target.cases.txt`: the 36 cases of the key `new-target` of `docs/plan/slice-08/scan.tsv` (the cases with `new.target` and no class, `super` or private name; negative parse cases among them 13). By directory: `language/expressions/new.target` 9, `language/expressions/{prefix,postfix}-{increment,decrement}` 8 and `assignment` 2 (assignment targets), `language/eval-code` 4, async functions and methods 6, `language/expressions/arrow-function` 2, `language/global-code` 2, `built-ins/Array/prototype/flatMap` 2 (a species constructor that reads `new.target`), `built-ins/Function/prototype/bind` 1. Their 72 runs fail on the plan's base run, 64 on `new.target is not supported before slice 8` and 8 as counted refusals. The base run of this plan is the full run of 2026-11-26 on `149e12f1`, whose total line `test262 total 53801 8982 7 44812 25943 18867 2` and slice lines equal `conformance/test262/expected.txt` on `62c7cf59`; its slice line 8 is `test262-slice 08 9302 18455 0 0 9302 5 9297 0`. Design it builds on: decision 3 of `docs/design/engine.md`, "`this` and `arguments` in an arrow function" (an arrow function has no `new.target` of its own; item 1, the `this` taken when the arrow is made). Design change 3 of this decomposition, written into that paragraph by a design author before the unit starts: an arrow function takes `new.target` and the function its `this` comes from (the nearest function that is not an arrow, or none) when it is made, as it takes `this`, kept with it in one box in place of `lexical_this` so that `ObjectRecord` keeps its size (`object::generator::tests::a_generator_keeps_the_object_record_at_its_size`, 200 bytes); and the frame of a [[Construct]] holds its NewTarget. Design change 4: PerformEval's four flags are read from that function (the running frame's function, or the one an arrow took), and passed to `swell_syntax::parse_eval_with` as one value. The unit reads the text that landed and follows it where it differs from this story.

## What later stories reuse

The frame's NewTarget (read by the class constructors of `story:class-definition-evaluation` and by `super()`, `story:derived-classes-and-super-call`, which passes it on); the arrow's box with the function its `this` comes from (`story:derived-classes-and-super-call` reads [[HomeObject]] through it for `super` in an arrow); the eval context value and its four flags (`story:derived-classes-and-super-call` reads `inMethod` and `inDerivedConstructor`, `story:eval-in-class-field-initializers` `inClassFieldInitializer`); the parser's flag that admits `new.target` (`story:class-element-syntax-and-early-errors` sets it in field initializers and static blocks).

## Change

Failing tests first: the tests and fixtures below are written before the code and fail on the base (the parser refuses `new.target`).

- `crates/syntax/src/parser/expression.rs`, `new_rest`: `new . target` is the node `Expr::NewTarget` (`crates/syntax/src/ast.rs`, a new variant), with `target` written without an escape (`escaped-target.js`) and `new` too (`escaped-new.js`); it stands where a function that is not an arrow encloses it, an arrow taking the answer of the code around it (a flag of `Parser` beside `yields` and `awaits`, saved and put back at each function boundary in `crates/syntax/src/parser/function.rs`, `save_context`, `open_context` and `function_close`), and anywhere else it is the early error of `#sec-scripts-static-semantics-early-errors` ("It is a Syntax Error if StatementList Contains NewTarget unless the source text containing NewTarget is eval code that is being processed by a direct eval" with `inFunction`). `new.target` is not a valid assignment target (`++new.target`, `new.target = 1`, the `prefix-*` and `postfix-*` cases), checked in `crates/syntax/src/early.rs`.
- The eval entry: `swell_syntax::parse_eval` and `parse_eval_with` (`crates/syntax/src/lib.rs`) take one value of the eval context (its four flags, design change 4) in place of `strict_caller` alone; `new.target` in eval code is admitted when `inFunction` is true. - `swell-compiler`: `Expr::NewTarget` compiles to an instruction that pushes the frame's NewTarget, or `undefined` (`crates/compiler/src/bytecode.rs`, its `Instruction` variant and its documentation; `disasm.rs`; `expression.rs`, the arm; `resolve.rs`, the arm of the walk, which binds nothing). `ArrowClosure` takes the NewTarget and the function the `this` comes from with the `this` it takes.
