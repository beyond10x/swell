## Context

Slice 8 of 19, `classes` (`epic:slice-08-classes`; `docs/design/engine.md`, section 12, item 8: classes, `super`, `new.target`, private names, static blocks). This story is `new.target` (`#sec-meta-properties`, GetNewTarget `#sec-getnewtarget`) in every function that is not a class: its grammar and early errors, its value in a call (undefined) and in a [[Construct]] (the NewTarget the construct was given), in an arrow function (the `new.target` of the frame that made it), in a generator and an async function (always undefined: neither is a constructor), and in direct eval code (allowed only where PerformEval's `inFunction` is true, `#sec-performeval`). It needs no other story of slice 8: order 1, built beside `story:class-syntax-and-early-errors` and `story:super-property-and-super-syntax`. Slice 8 is built after slice 9 is delivered; no slice 9 story writes a file of this story but `crates/swell/tests/main.rs` (generated).

It also brings the two mechanisms of the design that every later story of the slice reads: what an arrow takes (item 4 of "`this` and `arguments` in an arrow function": the box `ArrowContext` with `this`, `new_target` and `function`, so that the `function` of every frame is the function GetThisEnvironment answers) and the eval frame's function with PerformEval's four flags (item 5 of that paragraph). This story reads `inFunction` only, and computes `inMethod` as item 5 states it (true in eval code of an object literal's method, whose `home_object` is set). `inDerivedConstructor` is false until `story:class-definition-evaluation` adds the box, which then answers it; `inClassFieldInitializer` is false until `story:eval-in-class-field-initializers`, which owns its read from the template kind `FieldInitializer` in `dynamic_code.rs` (the kind is `story:class-syntax-and-early-errors`'s, built beside this story).

On the base (the code of `62c7cf59`, unchanged by slice 9's plan; the unit reads every named site again on its own base): the parser refuses `new.target` at once (`crates/syntax/src/parser/expression.rs`, `new_rest`: `refuse_at("new.target", 8, start)`), the frame has no NewTarget (`crates/swell/src/interp/frame.rs`, `Frame`: `this`, `function`, `constructed`), an arrow keeps only its `this` (`EcmascriptFunction::lexical_this` in `crates/swell/src/object/ecmascript_function.rs`; `keep_lexical_this`), the eval frame's `function` is `None` (`crates/swell/src/dynamic_code.rs`, the `Frame` literal of `parse_eval_code`'s caller), and `swell_syntax::parse_eval_with` takes the source, `strict_caller` and the options. The refusal `new.target is not supported before slice 8` is part of section 12, item 8 (the entry "Each slice" of `docs/plan/waves.md`, "What later slices take over", checked for this slice: the four refusals that name slice 8, `class`, `super`, `new.target` and `private name`, are all parts of item 8).
